Banking Streamhouse Demo – Andi (C001)

Synthetic data · demo thresholds, not production policy · AI is advisory
The story: why this demo matters (click to hide)

The problem

Banks hold rich customer data, but it sits in separate systems and arrives in batches. When a premium customer starts moving money to another bank, the bank usually finds out after the money has gone. A single transfer or search looks normal on its own.

The streamhouse

Live events (what just happened) are joined with customer history from Db2 (what we know) by Flink, continuously. The result is one always-current customer state with a risk level and a reason (what is true now).

The action

An AI assistant reads that trusted state and recommends the next step (what we should do). The relationship manager decides. Nothing is sent to the customer automatically.

User guide: run the Banking Streamhouse demo

The demo follows one synthetic customer, Andi (C001), whose behavior changes over five events. You send the events, watch Kafka and Flink turn them into a customer state, then ask an AI agent for the next-best action. Allow about 7 minutes. The demo is already deployed on OpenShift (this page); you can also run it on your laptop.

1. Check the systems

Press the button, then fix anything marked not ready using section 6.

2. Open the demo

Option A: on OpenShift (recommended). Nothing to install.

  1. Open this page's address in a browser.
  2. Log in with user demo. The password is stored in the cluster; ask the demo owner or read it with: 
    oc -n streamhouse-demo get secret streamhouse-env \
  -o jsonpath='{.data.DEMO_PASSWORD}' | base64 -d
  3. The Db2 data and Kafka topics are already set up. Go to section 4.

Option B: on your laptop. Do the one-time setup in section 3, then:

  1. From the repository folder run ./start-demo.sh and leave the window open.
  2. Open http://localhost:8000/.
Both options use the same Db2, Kafka (Confluent VM) and Orchestrate. Do not run the same scenario from two places at once.

3. One-time setup (laptop only)

  1. Install Python 3.9 or newer, then from the repository folder: 
    pip install -r backend/requirements.txt
  2. Copy the settings template and fill it in. .env.local is git-ignored and must never be committed: 
    cp .env.example .env.local
    You need the Db2 and Orchestrate credentials files, the Kafka user and password, and the Kafka bootstrap list.
  3. Download the Kafka CA certificate from the Confluent VM: 
    scp -i cflt-vsi-key.pem root@<vm-ip>:/var/lib/confluent-access/kafka-ca.crt backend/certs/kafka-ca.crt
  4. With the server running, create the Db2 tables, the sample customer and the Kafka topics. seed deletes all demo data in Db2 before reloading Andi, so run it deliberately: 
    curl -X POST localhost:8000/api/admin/schema
curl -X POST localhost:8000/api/admin/seed
curl -X POST localhost:8000/api/admin/topics

Needed for both options: the Flink statements cs4 (customer state) and al1 (alerts) must be RUNNING on Confluent Manager for Apache Flink. Their SQL is in flink/.

curl -sk -u admin:<password> https://<vm-ip>/cmf/api/v1/environments/flink-env/statements
The Confluent environment on TechZone expires on a set date. Extend it beforehand and re-check cs4 and al1 after any restart.

4. Get ready and know the page

  1. Press Check systems above: Db2, Kafka and Orchestrate should all be ready.
  2. Press Reset in the generator. This clears the previous run, starts a new one and republishes Andi's history to Kafka.
  3. Check the state card: LOW, savings IDR 127M.
AreaMeaning
Pipeline stripStages light up when a real record reaches them. Counters are real.
Transaction generatorSends the scripted events. Each one is written to Db2 (audit) and published to Kafka.
Data viewerLive records from Kafka, Andi's history from Db2, and the Flink SQL that does the scoring.
Customer stateWritten by Flink, not by the browser. Shows balance, transfers, search, card use, risk and reason.
AI assistantSends only the state to the watsonx Orchestrate agent. The answer and the RM decision are logged to Db2.

5. Run the demo

Press Send next event once per step, or Auto-play (one event every 6 seconds). The state card updates a few seconds after each event while Flink processes it.

#EventExpectSay
1Salary +IDR 35MLOW balance IDR 162MA normal event. The raw record is in the bank.transactions tab.
2External transfer -IDR 80MMEDIUM balance IDR 82MEight times Andi's normal external transfers. The history from Db2 gives the event its meaning.

  1. After step 4 or 5 press Ask agent for next-best action. Wait about 10 to 20 seconds.
  2. Read the Assessment, Evidence and Recommended action. Open Prompt sent to the agent to show that only the state was sent.
  3. Press RM approves outreach or Dismiss. Nothing is sent to the customer. The decision is logged to Db2.
  4. To run again, press Reset.

6. If something goes wrong

SymptomLikely causeWhat to do
Browser keeps asking for a login (OpenShift)Wrong password.Read the password from the cluster secret (section 2, option A).
Page does not load (OpenShift)The pod is not running.oc -n streamhouse-demo get pods. If it is not Running, oc -n streamhouse-demo rollout restart deploy/streamhouse-demo.
Page says "Backend not reachable" (laptop)Server not running or crashed.Run ./start-demo.sh again and reload. If the port is busy: lsof -ti tcp:8000 | xargs kill.
Check systems shows Db2 not readyWrong or missing Db2 credentials, or no network.Laptop: check DB2_CONFIG_FILE in .env.local. OpenShift: check the streamhouse-files secret.
Check systems shows Kafka not readyVM unreachable, wrong password, or missing CA file.Check the Kafka settings and that ports 9094 to 9096 are reachable. The Confluent environment may have expired.
Events appear in bank.transactions but the state card never changesThe Flink statements are not running.Check cs4 and al1 (section 3). Wait 15 seconds before concluding.
State shows an old runReset was not pressed.Press Reset.
Agent answer starts with "SIMULATED"Orchestrate was unreachable. The page labels this on purpose.Check the Orchestrate credentials and the agent name (banking_rm_assistant). Tell the audience it is simulated, or retry.
Everything is slow after a long idle periodIdle Kafka connections were dropped.Press the button again, or restart the server or pod.
You changed the code (OpenShift)The image is built from committed files.Commit, then follow "Update after a code change" in deploy/DEPLOY.md.

7. Say this to the audience

  • All customers, balances and events are synthetic.
  • The risk thresholds are illustrative demo logic, not production policy.
  • The AI advises. A human relationship manager approves any action. Nothing is sent to the customer automatically.
  • The streamhouse complements the data warehouse and core banking. It does not replace them.
